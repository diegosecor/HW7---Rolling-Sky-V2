# Rolling Sky — 2D Skyline Run

**Original game design, specification and foundation: [sharon5u](https://github.com/sharon5u/gamegame).**

Phase 2 implementation and visual polish: Diego, with AI assistance documented in `prompt_log.md`.

This version follows the original top-down 2D specification. It starts from the author's received project, rather than from the separate experimental chase-camera version. The original course generation, gameplay engine, controls, scoring and two-level structure remain the foundation.

## Run

Open `index.html` in a modern browser. Everything is local: no installation, dependencies, server, build step or internet connection is required.

- Left / right arrows: steer.
- Up: jump across gaps. Obstacles are tall and must be avoided.
- P: pause or resume.
- Space: restart after losing or winning.
- Audio button: toggle synthesized background music and effects.
- Touch buttons appear on small screens or coarse-pointer devices.

The ball moves forward automatically. Collect cyan diamonds, avoid obstacles and reach the checkered finish. Azure ascent is the introductory course; Violet velocity is faster and has extra obstacles. Both retain the original nightfall and crosswind sections. The menu hides during play and returns on the results screen.

1. Keep the inherited engine and course logic.

4. Improve readability and finish the presentation.

The view has no vanishing point, camera tilt or distance-dependent scale. Jump height changes the ball's scale and shadow, rather than moving its ground position forward.

## Pixel-art direction

The visual layer is now an original pixel-art garden, rendered at 300 × 360 pixels for a 600 × 720 world and enlarged without smoothing. Azure ascent uses luminous wetlands, teal stone and mossy greens; Violet velocity uses moonflowers, lavender stone and a mauve-blue pond. Band-based gradients, sparse dithering, chipped tile corners, engraved stones, moss, blossoms and lily pads give the board a hand-painted pixel texture.

The inherited moving duck has three feather palettes, a shaded head and neck ring, patterned wings, webbed feet, blinking and discrete walking poses. Frogs, koi, butterflies, lotus flowers and fireflies decorate the margins. These decorative animals never participate in collisions; amber corner markers identify actual obstacles. The sphere and diamonds also use stepped pixel shading. The menu includes a small animated field-guide illustration and a matching pixel-style frame.

All art is generated by local JavaScript rectangle painters. There are no downloaded image assets or additional runtime packages. Decorative animation stops for reduced-motion preferences.

## Verification

### Complete visual refinement

The second art pass covers the complete board, rather than only the animal sprites. The player is a shaded gold sphere with a rotating teal inlay, layered contact shadows and a matching menu portrait. Its jump enlargement is repainted on the pixel grid to avoid soft edges from fractional scaling.

The two routes use different stone palettes with worn lotus inlays, mineral grain, moss, grass strips and scalloped edging. The water background includes irregular banks, reeds, reflections, pond animals and fireflies. Bushes, mossy rocks and mountain-crystal clusters replace the old nested block shapes. Cyan diamonds, recessed gaps with striped lips, bitmap score effects, a labeled finish line and a laurel medal complete the same visual direction. The original engine, course layouts and specification were not edited during this pass.

Static native-canvas renders were inspected for both routes, a jump, nightfall, the finish and the victory medal. This verifies the drawing code's appearance; interactive browser layout, audio and touch remain manual checks.

With Node.js 18 or newer, run `npm test`. No package installation is needed. The equivalent command is:

```text
node --test test-engine.js test-effects.js test-spec.js test-pixel-art.js
```

Tests traverse both courses and exercise gameplay, effects, input and acceptance behavior. Orthographic checks verify constant scale and 84-pixel tile widths at different distances and in both routes. Automated renderer checks use a simulated canvas, not a real browser screenshot. Static raster previews of both boards and the field guide were additionally rendered with a native canvas and visually inspected.

## Known limitations and deliberate tradeoffs

- Interactive playtesting of the complete interface in the user's browser is still needed. Reviewing static raster art does not verify browser layout, audio or touch behavior.
- Browsers require user interaction before audio can start. Audio is muted initially.
- Some browsers restrict local storage for local files; the game remains playable but cannot guarantee persistent best scores in that case.
- Art and music are procedural to keep the project portable and asset-free. This is an arcade jump used for gap clearance, not a 3D physics simulation.
- The original start/loss/win structure is preserved. The impact/fall animation deliberately delays the result message, while the world stops immediately.
